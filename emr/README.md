# 電子カルテ（試作）

診療所向けの電子カルテです。**インターネットは不要**で、院内だけで動きます。使い方は2通りあります。

| 使い方 | 準備 | データの保存先 |
| --- | --- | --- |
| **1台だけで使う** | `emr/index.html` をダブルクリックするだけ | そのパソコンのブラウザ内 |
| **院内の複数台で使う**（受付・診察室・iPad など） | 1台を「親機」にして起動ファイルをダブルクリック。ほかの端末はブラウザで親機のアドレスを開くだけ | 親機の `emr/server/data/` |

👉 **院内ネットワークの設定方法は `guide.html`（接続ガイド）** に、はじめての人向けに手順を書いています。親機を起動すると自動で開き、子機で入力するアドレスと QR コード、つながっている端末の一覧もその場で表示されます。

どちらの場合も、カルテの内容はすべて**端末の中で暗号化してから**保存・送信します。親機のパソコンや院内の通信を盗み見られても、カルテの内容は読めません。

## 院内ネットワーク版のしくみ（かんたんに）
- 親機 `server/server.js` は Node.js だけで動きます（追加インストールなし）。起動ファイル: `電子カルテを起動（Windows）.bat` / `電子カルテを起動（Mac）.command` / `start-linux.sh`
- 子機は `http://親機のアドレス:8080` をブラウザで開くだけ。ほかの端末での変更は**自動で画面に反映**されます
- 2台で同じものを同時に変更したときは、あとの保存を止めて「最新の内容を読み込む」を案内します（上書き事故の防止）。患者番号・監査ログも同時に記録して重なりません
- 親機は院内（プライベートIPアドレス）からの接続だけを受け付け、読み書きには暗号鍵から作った署名が必要です
- 停電に備えて1件ごとにディスクへ書き込み、毎日自動でバックアップ（30日分）を作ります
- 子機が `http://192.168.x.x` で開く場合、ブラウザ内蔵の暗号機能が使えないため、同じ方式の純 JavaScript 実装（`js/jscrypto.js`、標準実装と照合済み）で暗号化します
- 親機が止まると子機に「サーバー未接続」と表示し、戻れば自動で再開します
- 「1台だけで使う版」のデータは、バックアップファイルから院内サーバー版へ引き継げます

## できること
| 業務 | 内容 |
| --- | --- |
| 受付 | 当日の受付一覧（診察待ち→診察中→会計待ち→完了）、待ち時間表示、取消（理由必須）、重複受付の確認 |
| 患者 | カナ・漢字・患者番号・電話・生年月日（8桁）で検索、新患登録（同姓同名同生年月日の重複チェック）、保険・緊急連絡先・アレルギー（「なし（確認済み）」と「未確認」を区別）、変更履歴 |
| カルテ | 2画面（左：過去の記載／右：本日の記載）、SOAP＋バイタル（BMI自動計算）、定型文・病名・受付時主訴の挿入、自動下書き保存、Ctrl+Enter で確定 |
| 真正性 | 確定後の修正は**理由必須で新しい版**として保存（上書きしない）。版ごとの差分表示とハッシュ照合。削除も理由つきの論理削除 |
| 処方 | 一般名・商品名・ひらがなで薬品検索、内服/頓服/外用、前回Do・過去処方のDo、院外/院内、変更不可、処方箋印刷、取消（理由必須） |
| 処方チェック | アレルギー（商品名で登録しても一般名処方で検出、アスピリン喘息→NSAIDs）、同効薬重複、相互作用、高齢者注意。アレルギー警告を押し切るには理由の入力が必要で、監査ログに残る |
| 病名 | ICD-10 付き、主病名・疑い、転帰（治癒・中止など）と転帰日 |
| 検査 | 結果入力、時系列の表（H/L 表示）、eGFR 自動計算、項目ごとの経過グラフ |
| 経過グラフ | 血圧・脈拍・体重・体温・SpO₂・HbA1c（ホバーで値表示、表でも確認可） |
| 文書 | 診療情報提供書（病名・既往歴・直近の経過・検査・処方を自動で下書き）、診断書、印刷 |
| 権限 | 医師／看護師（看護記録・バイタル・検査入力のみ、処方不可）／医療事務（受付・患者登録のみ、診療内容は見えない）＋管理者 |
| 管理 | 利用者の追加・停止・パスワード再発行、施設情報、自動ロック時間、バックアップ・復元 |
| 監査ログ | 閲覧・登録・変更・印刷・ログインをすべて記録。ハッシュチェーンで改ざん・欠落を検出、CSV 出力 |

## 安全のしくみ
- **暗号化**: すべての診療データを AES-GCM 256bit で暗号化。鍵は各利用者のパスワードから PBKDF2-SHA256（60万回）で作った鍵で包んで保存。パスワードがなければ端末やバックアップを盗まれても読めない
- **改ざん検出**: 各レコードは自分の ID を認証データに含めて暗号化（差し替え・書き換えは復号時に検出）。監査ログとカルテの版はハッシュでつながっている
- **利用停止** はその人の「包んだ鍵」を削除するので、パスワードを知っていても開けなくなる。権限は暗号化した側の情報で判定する
- ログイン5回失敗で5分ロック、一定時間操作がないと自動ロック（Ctrl+L で即ロック）、同じブラウザで2つのタブを同時に開けない

## 実運用の前に必要なこと（この試作では未対応）
これは「本気の試作」であって、そのまま患者さんの診療に使える認証済み製品ではありません。
- **ガイドライン対応**: 厚労省「医療情報システムの安全管理に関するガイドライン」（第6.0版）への適合確認、運用管理規程の整備
- **マスター**: 薬品・病名・検査はサンプル。MEDIS 標準病名マスター、医薬品マスター、最新の添付文書に基づく相互作用データに置き換えること
- **レセプト・会計**: 点数計算・レセプト作成・オンライン資格確認・電子処方箋には未対応
- **院内サーバー版の注意**: 通信は http（院内LAN）。カルテの内容は暗号化されていますが、院内 Wi-Fi に不正な機器が入ると画面のプログラム自体を改ざんされる余地があるため、Wi-Fi のパスワード管理・ゲスト Wi-Fi の分離が前提です。利用停止した人の暗号鍵の作り直し（鍵ローテーション）は未対応
- **電子署名**: HPKI による電子署名、タイムスタンプには未対応
- **バックアップ**: ブラウザのデータは消える可能性がある。管理画面から定期的に外部媒体へ書き出すこと（7日以上取っていないと警告）
- 処方箋の様式は簡略版。正式様式との一致を確認すること

## テスト
```
npm i playwright                 # 初回のみ
node emr/tests/crypto-test.js    # 純JS暗号が標準実装と同じ結果になるか（NISTのテスト値＋乱数照合）
node emr/tests/e2e.js            # 1台版: 診察→処方→修正→検査→権限→改ざん検出（33項目）
node emr/tests/e2e-server.js     # 院内サーバー版: 親機＋子機の同時操作・衝突・停止と復帰・移行・接続ガイド（25項目）
```
